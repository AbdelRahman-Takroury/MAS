# MAS — Smart Farm AI

مشروع محلي لإدارة مزرعة بندورة ومتابعة الري والمصاريف والحصاد والمبيعات، مع واجهة عربية وإنجليزية، محاكاة، مساعد استشاري، تقارير PDF وصوت عربي اختياري.

هذا الدليل مخصص لتشغيل المشروع **من الصفر على جهاز جديد**. الأوامر الأساسية مكتوبة لـ **Windows PowerShell**. لا تحتاج VS Code أو Codex لتشغيل الموقع؛ يمكن استعمالهما لتحرير الملفات فقط.

## 1. نقل المشروع والمتطلبات

### الملفات التي يجب نقلها

انسخ المجلد الذي يحتوي **مباشرةً** على `README.md` و`requirements.txt` و`alembic.ini`، وليس المجلد الخارجي فقط. مثال للمسار على الجهاز الجديد:

```text
C:\Projects\MAS-Abdel_Rahman
```

احتفظ بالمجلدات `backend`, `public`, `data`, `docs`, `contracts`, `tests` والملفات الموجودة في جذر المشروع. خطوط PDF ومكتبات الواجهة موجودة داخل `public/assets`؛ يجب نقلها كاملة.

لا تنقل `.venv` أو `node_modules` أو `__pycache__`؛ يعاد إنشاء بيئة التشغيل على الجهاز الجديد. لا تشارك `.env` المحتوي على مفاتيح خاصة. أنشئه من `.env.example`. إذا أردت نقل السجلات، اتبع قسم نقل البيانات بدل خلط قاعدة العمل بقاعدة اختبار.

يمكن تنزيل المشروع كملف ZIP من GitHub ثم فك ضغطه، أو استنساخه بعد تثبيت Git:

```powershell
git clone https://github.com/AbdelRahman-Takroury/MAS.git
Set-Location MAS
```

المستودع: https://github.com/AbdelRahman-Takroury/MAS — استعمل فرع `main`. فحص التسليم الأصلي تم على مجلد محلي بدون Git قبل رفع هذه النسخة.

### البرامج المطلوبة

| البرنامج | متى تحتاجه؟ |
| --- | --- |
| Python 3.12 مع pip | لتشغيل الخادم محليًا؛ هذه النسخة استخدمت في التحقق |
| متصفح حديث | لفتح الموقع؛ التحقق الفعلي كان على Google Chrome |
| اتصال إنترنت | لتثبيت الاعتماديات أول مرة، ولخدمات الطقس/الذكاء/الصوت الحية عند استخدامها |
| Node.js وnpm | فقط لاختبارات JavaScript والمتصفح؛ ليسا مطلوبين لتشغيل الموقع العادي. التحقق استخدم Node 24.19.0 |
| Docker Desktop مع Docker Compose | فقط إذا اخترت مسار Docker بدل Python المحلي |
| PostgreSQL 16 | إذا أردت قاعدة PostgreSQL محلية؛ لا تحتاج تثبيته منفصلًا عند استخدام Docker |

في مثبت Python على Windows فعّل **Add Python to PATH**. بعد التثبيت افتح PowerShell جديدًا وتحقق:

```powershell
py -3.12 --version
```

إذا كان أمر `py` غير موجود لكن `python --version` يعرض Python 3.12، استعمل `python` بدل `py -3.12` في أمر إنشاء البيئة فقط.

## 2. التشغيل المحلي من الصفر — SQLite

هذا المسار لا يحتاج Docker أو تثبيت PostgreSQL. SQLite تأتي مع Python، والواجهة يقدمها نفس الخادم؛ لا يوجد خادم frontend أو خطوة build منفصلة.

### الخطوة 1: افتح مجلد المشروع الصحيح

```powershell
Set-Location 'C:\Projects\MAS-Abdel_Rahman'
Get-ChildItem
```

استبدل المسار بمكان المجلد عندك. يجب أن ترى `requirements.txt` و`alembic.ini` و`backend` و`public`.

### الخطوة 2: أنشئ بيئة Python وثبت الاعتماديات

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

نستخدم Python الموجود داخل `.venv` مباشرةً؛ **لا تحتاج تفعيل البيئة أو تغيير PowerShell Execution Policy**. لا تنسخ `.venv` من الجهاز القديم.

### الخطوة 3: أنشئ ملف الإعدادات

نفذ النسخ التالي فقط إذا لم يكن لديك ملف `.env`؛ لا تستبدل إعدادات موجودة:

```powershell
if (!(Test-Path '.env')) { Copy-Item '.env.example' '.env' }
notepad .env
```

لتجربة محلية جديدة، اضبط السطر التالي داخل الملف:

```dotenv
DATABASE_URL=sqlite:///./mas_local_demo.sqlite
```

اترك `GROQ_API_KEY`, `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION` فارغة إذا لم تتوفر مفاتيح. ملف قاعدة SQLite سيُنشأ داخل مجلد المشروع. لا تشير إلى قاعدة بيانات تشغيل حقيقية أثناء التجربة.

**تنبيه للإعدادات:** متغيرات PowerShell تتقدم على قيم `.env`. إذا كنت قد نفذت اختبارات في نفس النافذة، افتح نافذة جديدة قبل التشغيل العادي، أو أزل المتغير المؤقت تحديدًا:

```powershell
Remove-Item Env:DATABASE_URL -ErrorAction SilentlyContinue
```

### الخطوة 4: أنشئ الجداول وأضف المزرعة التجريبية

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m backend.app.seed
.\.venv\Scripts\python.exe -m alembic current
```

- Alembic يطبق ترحيلات قاعدة البيانات. الرأس الحالي: `20261010_0003`.
- seed ينشئ مزرعة تجريبية معلّمة بوضوح؛ تكراره لا يعيد إنشاء نفس المزرعة ولا يعيد ضبط تخصيص مياه موجود.
- القيمة 4,000 لتر تخص بيانات المزرعة التجريبية فقط. المزارع الجديدة لا تحصل على كمية مياه مفترضة.

### الخطوة 5: شغّل الخادم

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8001
```

اترك نافذة PowerShell مفتوحة. عندما يظهر `Uvicorn running on http://127.0.0.1:8001` افتح:

| الصفحة | الرابط |
| --- | --- |
| لوحة التحكم | http://127.0.0.1:8001/dashboard.html |
| الصفحة الرئيسية | http://127.0.0.1:8001/ |
| توثيق API التفاعلي | http://127.0.0.1:8001/docs |
| OpenAPI JSON | http://127.0.0.1:8001/openapi.json |
| فحص الخادم | http://127.0.0.1:8001/health/live |
| فحص اتصال قاعدة البيانات | http://127.0.0.1:8001/health/ready |

يجب أن يعيد فحص الجاهزية:

```json
{"status":"ok","database":"available"}
```

هذا الفحص يتحقق من اتصال قاعدة البيانات، ولا يثبت أن Groq أو Azure أو الطقس متصلون. فتح `/docs` وحده لا يثبت وجود الجداول؛ نفذ الترحيلات ثم افتح لوحة التحكم وتحقق من المزرعة.

**لا تفتح `dashboard.html` مباشرةً كملف، ولا تشغله عبر VS Code Live Server**؛ افتحه من عنوان FastAPI أعلاه كي تعمل مسارات `/api` والملفات معًا.

### Linux / macOS

من داخل مجلد المشروع، المسار المحلي نفسه يعمل مع اختلاف أوامر البيئة:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
[ -f .env ] || cp .env.example .env
# Edit .env and set DATABASE_URL=sqlite:///./mas_local_demo.sqlite
.venv/bin/python -m alembic upgrade head
.venv/bin/python -m backend.app.seed
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8001
```

هذه أوامر مكافئة؛ التحقق الفعلي في هذه المراجعة تم على Windows.

## 3. التشغيل اليومي والإيقاف

بعد اكتمال التثبيت، يكفي:

```powershell
Set-Location 'C:\Projects\MAS-Abdel_Rahman'
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8001
```

- للإيقاف: `Ctrl+C` داخل نافذة الخادم. السجلات محفوظة في قاعدة البيانات.
- لإعادة التشغيل: نفذ نفس أمر uvicorn؛ لا تنشئ قاعدة جديدة كل مرة.
- بعد تحديث الكود واعتمادياته: خذ نسخة احتياطية من بياناتك، ثبت `requirements.txt` مجددًا ثم نفذ `alembic upgrade head` باستخدام البيئة نفسها.
- تحديث HTML/CSS/JavaScript يحتاج تحديث المتصفح، و`Ctrl+F5` إذا كان يعرض نسخة قديمة.
- تعديل `.env` يحتاج إعادة تشغيل الخادم.
- المنفذ في التشغيل المحلي تحدده `--port`؛ `API_PORT` في `.env` مستخدم لمسار Docker.

`127.0.0.1` يشير دائمًا إلى **الجهاز الذي فتحت عليه المتصفح**. بعد نقل المشروع وتشغيله على الجهاز الثاني افتح الرابط من الجهاز الثاني نفسه. مشاركة الموقع عبر الشبكة أو الإنترنت ليست مفعلة في هذا الدليل؛ المشروع لا يتضمن مصادقة مناسبة للنشر العام.

## 4. الوضع التجريبي بدون مزودين خارجيين

إذا أردت العرض الذي استخدم في اختبارات التسليم، بدون طلبات مباشرة إلى Groq/Azure/Open-Meteo، استعمل الخادم المخصص بعد تثبيت Python:

```powershell
.\.venv\Scripts\python.exe tests/handoff_server.py --database-url sqlite:///./mas_handoff_browser.sqlite --port 8891
```

افتح http://127.0.0.1:8891/dashboard.html.

هذا الأمر يطبق الترحيلات ويضيف المزرعة التجريبية تلقائيًا، ويستخدم طقسًا اصطناعيًا ومساعدًا احتياطيًا، ويعطّل مفاتيح Groq وAzure داخل عملية الاختبار. يرفض أسماء قواعد البيانات التي لا تبدأ بـ `mas_handoff_`. لا تشغله على بيانات تشغيل حقيقية. التثبيت الأول للاعتماديات يحتاج الإنترنت، لكن مزودي الخدمة الخارجيين غير مستخدمين في هذا الوضع.

يوجد أيضًا `/dashboard.html?demo=1` لبيانات الواجهة النموذجية. هذا الوضع مختلف عن خادم QA أعلاه، وليس دليلًا على أن عمليات الحفظ أو مزودي الخدمات يعملون.

## 5. إعدادات البيئة والخدمات الاختيارية

| المتغير | وظيفته |
| --- | --- |
| `DATABASE_URL` | عنوان قاعدة البيانات؛ مطلوب |
| `GROQ_API_KEY` | مفتاح Groq الخاص بالخادم؛ اختياري |
| `GROQ_MODEL` | النموذج المحفوظ في المشروع: `openai/gpt-oss-20b` |
| `AZURE_SPEECH_KEY` | مفتاح Azure Speech؛ اختياري |
| `AZURE_SPEECH_REGION` | منطقة مورد Azure Speech المطابقة للمفتاح |
| `CORS_ORIGINS` | مصادر frontend الإضافية المسموحة، مفصولة بفواصل؛ الواجهة المدمجة تعمل من نفس المصدر |
| `WEATHER_CACHE_DIR` | مجلد قابل للكتابة لحفظ توقعات كاملة ومفصولة حسب الموقع |
| `WEATHER_SNAPSHOT_PATH` | مسار قديم لبعض الاستدعاءات المباشرة؛ التطبيق يستعمل cache مفصولًا حسب الموقع |
| `DEMO_USER_ID` | مالك محلي تجريبي؛ ليس نظام تسجيل دخول |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | إعدادات حاوية PostgreSQL في Compose |
| `API_PORT` | منفذ المضيف عند تشغيل Compose؛ الافتراضي 8001 |

### المساعد Groq

ضع مفتاحك في `.env` مع النموذج الحالي، ثم أعد تشغيل **الخادم العادي**. عند غياب المفتاح أو فشل المزود، يظل الرد الاحتياطي الحتمي متاحًا بالعربية والإنجليزية. لا يلزم مفتاح لتشغيل الموقع. خادم QA في القسم السابق يعطّل المزود حتى لو كتبت المفتاح في `.env`.

### الطقس

الخادم العادي قد يطلب توقعات Open-Meteo عند فتح مزرعة أو إجراء حساب. التطبيق الحالي لا يطلب مفتاح Open-Meteo. يحفظ فقط التوقعات الحية الكاملة والمتحقق منها؛ ويستخدم النسخ المحفوظة عند صلاحيتها. تعذر الاتصال وغياب نسخة صالحة يظهر كبيانات غير متاحة، وليس صفرًا. لا تنسخ snapshot لمزرعة مختلفة بهدف ملء البيانات الناقصة.

### الصوت

أدخل مفتاح ومنطقة Azure Speech المتطابقين وأعد تشغيل الخادم العادي. الصوت العربي المحدد هو `ar-JO-TaimNeural`. عند غياب الخدمة تظهر رسالة واضحة؛ fallback المتصفح اختياري ويتطلب صوتًا عربيًا مثبتًا/متاحًا على الجهاز. لا تظهر بيانات مزيفة على أنها تسجيل صوتي ناجح.

لا تضع مفاتيح في `public/` أو ملفات JavaScript، ولا ترفق `.env` في نسخة تشاركها. تفعيل الخدمات الحية قد يستهلك حصص حسابك؛ فحوص التسليم لم تتحقق من الاتصال الحي لهذه الخدمات.

## 6. PostgreSQL وDocker

### المسار A: Docker Compose

على الجهاز الجديد ثبّت Docker Desktop وشغّله، وتحقق من أن Docker Engine يعمل:

```powershell
docker version
docker compose version
```

من جذر المشروع، أنشئ `.env` من `.env.example` كما في القسم 2. اضبط `POSTGRES_DB`, `POSTGRES_USER` وكلمة مرور جديدة في `POSTGRES_PASSWORD` بدل `change-me`، والمنفذ المطلوب في `API_PORT`. Compose يبني `DATABASE_URL` للحاوية من متغيرات PostgreSQL ويستخدم اسم المضيف الداخلي `db`؛ قيمة SQLite في `.env` لا تتحكم بقاعدة الحاوية.

```powershell
docker compose -p mas_local up --build -d
docker compose -p mas_local ps
docker compose -p mas_local logs --tail 100 api
```

الخادم داخل الحاوية ينفذ الترحيلات وseed قبل التشغيل. افتح http://127.0.0.1:8001/dashboard.html إذا بقي `API_PORT=8001`.

```powershell
# Stop without deleting data
docker compose -p mas_local stop
# Start the existing containers again
docker compose -p mas_local start
# Restart containers
docker compose -p mas_local restart
```

استخدم اسم المشروع نفسه `mas_local` في كل مرة لاستعمال volumes نفسها. تغييره ينتج بيئة أخرى وقد تبدو البيانات غير موجودة. **لا تستخدم `down -v` إذا أردت الاحتفاظ بالسجلات**؛ هذا الخيار يحذف volumes. تغيير كلمة مرور `.env` بعد تهيئة volume لا يغيّر تلقائيًا كلمة مرور المستخدم داخل PostgreSQL الموجود.

عند مشاركة ملفات المشروع لا تنتقل بيانات Docker volumes تلقائيًا. نقلها يحتاج dump/restore لقاعدة PostgreSQL منفصلًا عن نقل الكود. لا تستخدم أوامر إعادة ضبط قاعدة البيانات كحل لمشكلة اتصال.

### المسار B: PostgreSQL مثبت محليًا

ثبت PostgreSQL 16، ثم من pgAdmin أنشئ قاعدة جديدة باسم مثل `mas_local` وحدد مستخدمًا وكلمة مرور لها. اجعل المستخدم مالك القاعدة/قادرًا على إنشاء الجداول والترحيلات. داخل `.env`:

```dotenv
DATABASE_URL=postgresql+psycopg://YOUR_USER:YOUR_URL_ENCODED_PASSWORD@127.0.0.1:5432/mas_local
```

استبدل الرموز بقيم جهازك. كلمة المرور داخل URL تحتاج percent-encoding إذا احتوت رموزًا محجوزة مثل `@`, `:`, `/`, `#`, `%`. هذه القاعدة مختلفة عن SQLite؛ تغيير العنوان لا ينقل السجلات القديمة تلقائيًا.

ثم نفذ أوامر `alembic upgrade head` و`backend.app.seed` و`uvicorn` في القسم 2. لا تحتاج تعديل كود التطبيق.

### Docker للاختبار المعزول فقط

```powershell
docker compose -f compose.handoff.yml -p mas_handoff_pc2 up --build -d
```

هذه بيئة QA مستقلة بقاعدة PostgreSQL وvolume منفصلين، وطقس اصطناعي وبدون تحميل مفاتيح `.env` إلى API. رابطها http://127.0.0.1:8891/dashboard.html. اختر اسم مشروع فريدًا يبدأ بـ `mas_handoff_` واستعمله في جميع أوامرها. لا تشغلها بالتزامن مع خادم محلي على المنفذ 8891.

**حالة التحقق:** تم التحقق من صيغة ملف Compose، لكن تشغيل/إعادة تشغيل الحاويات لم يكن متاحًا في بيئة المراجعة بسبب حظر الوصول لمحرك Docker. تم بدلًا من ذلك التحقق من PostgreSQL 16.15 معزول محليًا، والترحيلات، والتزامن، واستمرار البيانات بعد إعادة تشغيل عملية قاعدة البيانات والخادم.

## 7. تشغيل الاختبارات

نفذ الاختبارات في نافذة PowerShell منفصلة عن نافذة التشغيل، ومن جذر المشروع.

### اختبارات Python

```powershell
$env:DATABASE_URL = 'sqlite+pysqlite:///:memory:'
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider
Remove-Item Env:DATABASE_URL
```

الاختبارات تنشئ قواعد معزولة وتستخدم محاكاة للمزودين. لا تضبط عنوان قاعدة عمل حقيقية للاختبارات.

### اختبارات JavaScript

ثبت Node.js مع npm أولًا. هذه الخطوات للاختبارات فقط:

```powershell
node --version
npm --version
npm install
npm test
```

`package.json` يحدد Playwright 1.62.1. يوجد كذلك `pnpm-lock.yaml` لمستخدمي pnpm؛ بيئة التسليم استعملت pnpm 11.25.0. عند استعمال pnpm نفذ `pnpm install --frozen-lockfile` ثم `pnpm test` بدل أوامر npm. لا تبدّل مديري الحزم داخل مجلد اعتماديات موجود دون إعادة تجهيز البيئة.

### فحص المتصفح والـ PDF

1. شغّل خادم QA من القسم 4 في نافذة أولى.
2. في نافذة ثانية، من جذر المشروع وبعد `npm install`:

```powershell
$env:HANDOFF_URL = 'http://127.0.0.1:8891'
$env:HANDOFF_OUTPUT = 'test-results/handoff'
$env:PLAYWRIGHT_CHROME_EXECUTABLE = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
npm run test:browser
```

إذا لم يكن Chrome في هذا المسار، استعمل مساره الصحيح أو ثبت Chromium الخاص بـ Playwright:

```powershell
Remove-Item Env:PLAYWRIGHT_CHROME_EXECUTABLE -ErrorAction SilentlyContinue
npx playwright install chromium
npm run test:browser
```

الفحص **يكتب سجلات** في قاعدة الخادم الذي تشير إليه `HANDOFF_URL`؛ استعمل خادم QA المخصص فقط. ينتج ملفات PDF وصورًا ونتائج JSON داخل `test-results/handoff`. يفحص الصوت بمحاكاة واضحة، وليس باستدعاء Azure حي أو الاستماع لصوت فعلي.

### اختبارات التزامن على PostgreSQL

أنشئ قاعدة اختبار مستقلة اسمها يبدأ بـ `mas_handoff_` ومستخدمًا يملك صلاحية إنشاء schemas:

```powershell
$env:DATABASE_URL = 'sqlite+pysqlite:///:memory:'
$env:TEST_POSTGRES_URL = 'postgresql+psycopg://YOUR_USER:YOUR_PASSWORD@127.0.0.1:5432/mas_handoff_tests'
.\.venv\Scripts\python.exe -m pytest -q tests/test_write_integrity.py -k competing
Remove-Item Env:TEST_POSTGRES_URL
Remove-Item Env:DATABASE_URL
```

الـ fixture يرفض أسماء القواعد الأخرى وينشئ schema فريدًا لكل حالة ويحذفه بعد الاختبار. لا يستبدل هذا قاعدة الإنتاج أو يفرغها.

آخر نتائج التسليم: **778 Python**، **17 JavaScript**، و**8 اختبارات تزامن إضافية على PostgreSQL** ناجحة. هذه نتائج المراجعة السابقة وليست ضمانًا أن الجهاز الجديد مجهز بشكل صحيح؛ نفذ الاختبارات عليه. توجد ملاحظة deprecation من Starlette/TestClient، وليست فشل اختبار.

## 8. تجربة النظام ونقل البيانات

### تسلسل تجربة بعد أول تشغيل

1. اختر المزرعة التجريبية أو أنشئ مزرعة وأدخل الإحداثيات والمساحة وتاريخ الزراعة ومرحلة المحصول ومعلومات الري.
2. عدّل الموسم: الحصاد المتبقي القابل للتسويق، السعر المفترض، المصاريف المتبقية، والمياه المتاحة باللتر مع بداية ونهاية الفترة.
3. فترة المياه يجب أن تطابق فترة التوقعات للحساب؛ تخصيص قديم أو بيانات ناقصة تظهر كغير متاحة. لا تفترض أن seed يجدد التخصيص كل يوم.
4. احفظ مصروفًا ثم راقب تغير الحسابات، وسجل الري والحصاد والبيع.
5. جرّب المحاكاة وقارن القيم الأساسية والافتراضية؛ المحاكاة لا تحفظ سجلات ولا تتوقع خسارة إنتاج بسبب العجز.
6. اسأل المساعد بالعربي والإنجليزي وراجع الأدلة والمصادر. مثال: «هل المياه المتاحة تكفي؟ اذكر المتاح والاحتياج والعجز باللتر والبيانات الناقصة».
7. حمّل PDF باللغتين، وجرّب الصوت إن كانت الخدمة أو أصوات المتصفح متاحة.

عند فشل حفظ برسالة شبكة أو رد غير مؤكد، أعد المحاولة بنفس النموذج؛ الواجهة تعيد استعمال مفتاح العملية. لعملية جديدة متعمدة، استعمل «سجل جديد» أو غيّر العملية. حالة إعادة المحاولة في ذاكرة الصفحة ولا تبقى بعد إغلاقها أو إعادة تحميلها.

### هل تريد نقل الكود فقط أم السجلات أيضًا؟

- **بداية جديدة:** انقل الكود، أنشئ `.env` جديدًا، ثم أنشئ قاعدة جديدة بالخطوات أعلاه.
- **SQLite مع سجلات:** أوقف الخادم قبل النسخ، وخذ نسخة احتياطية من ملف قاعدة البيانات المحدد في `DATABASE_URL`؛ لا تنسخ قاعدة قيد الكتابة كملف مفرد. انقلها للجهاز الجديد واضبط العنوان على مسارها. احتفظ بالأصل وطبّق الترحيلات على نسخة احتياطية أولًا قبل تحديث بيانات العمل.
- **PostgreSQL:** استعمل أدوات `pg_dump` و`pg_restore` المناسبة لإصدارك لنقل نسخة احتياطية إلى قاعدة جديدة. نسخ مجلد المشروع أو إنشاء `.env` لا ينقل بيانات PostgreSQL أو Docker volumes.
- **المفاتيح:** أدخلها محليًا على الجهاز الجديد بوسيلة خاصة؛ ليست جزءًا من حزمة الكود المشتركة.

ملفات weather cache ليست بديلًا عن قاعدة السجلات. اتركها تُنشأ من جديد عند توفر توقعات صالحة؛ لا تجعل مصدرًا قديمًا يبدو كأنه توقع حي.

## 9. حل المشاكل الشائعة

| المشكلة | ما الذي تراجعه؟ |
| --- | --- |
| `python` أو `py` غير معروف | ثبّت Python مع PATH، افتح terminal جديدًا، ثم تحقق من الإصدار |
| `No module named ...` | ثبت requirements باستخدام `.venv\Scripts\python.exe` وشغّل الخادم بنفس Python |
| `DATABASE_URL field required` | تأكد من `.env` في جذر المشروع ومن أنك تشغل الأوامر من ذلك المجلد |
| `no such table` / `relation does not exist` | نفذ `python -m alembic upgrade head` بالبيئة والعنوان نفسيهما المستخدمين للخادم |
| `Address already in use` / خطأ 10048 | أغلق خادمك السابق بـ Ctrl+C أو غيّر `--port` إلى 8002 وافتح رابط المنفذ الجديد |
| الرابط لا يفتح | تحقق من نافذة الخادم، ومن المنفذ، وافتح `/health/live`؛ الرابط المحلي لا يشير إلى جهاز آخر |
| `/health/ready` يعيد 503 | راجع DATABASE_URL، تشغيل PostgreSQL وكلمة المرور والمنفذ؛ لا تحذف البيانات لإصلاح الاتصال |
| تغييرات CSS أو الشات لا تظهر | `Ctrl+F5`؛ تأكد أنك فتحت نسخة المشروع الصحيحة والخادم الصحيح |
| الموقع فارغ من المزارع | تحقق من نجاح الترحيلات وseed ومن `DEMO_USER_ID` وعنوان القاعدة المستخدم |
| بيانات كانت موجودة ثم اختفت | راجع مجلد العمل لمسار SQLite النسبي أو اسم مشروع Docker؛ ربما تستخدم قاعدة مختلفة |
| الماء/الربح يظهر غير متاح | أكمل مدخلات الموسم والري، وتحقق من فترة المياه وتغطية الطقس؛ غير متاح ليس صفرًا |
| المساعد يعرض ردًا احتياطيًا | تحقق من إعداد Groq والخادم العادي؛ خادم QA يعطّل Groq عمدًا |
| الصوت غير متاح | تحقق من Azure region/key أو توفر صوت عربي في المتصفح؛ هذا لا يمنع وظائف السجلات |
| Docker engine غير متصل | شغّل Docker Desktop وانتظر جاهزيته؛ وجود أمر docker وحده لا يكفي |
| متصفح Playwright غير موجود | نفذ `npx playwright install chromium` أو اضبط مسار Chrome الصحيح |
| تغيير `.env` لا يؤثر | أعد تشغيل الخادم، وتحقق من متغيرات terminal التي قد تتقدم على `.env` |

## 10. بنية المشروع والحدود المعروفة

```text
backend/app/           FastAPI، النماذج، المسارات والخدمات
backend/engines/       الحاسبات الحتمية
public/                HTML / CSS / JavaScript / الصور والخطوط
data/                 بيانات ومصادر المشروع (ومجلد cache عند التشغيل)
contracts/            عقود الحاسبات
docs/                 توثيق الميزات ونتائج التكامل
tests/                اختبارات Python وJavaScript والمتصفح
alembic.ini           إعداد Alembic (مسار revisions محدد داخله)
requirements.txt      اعتماديات Python
package.json          أوامر واعتماديات اختبارات JavaScript
docker-compose.yml    تشغيل محلي عادي مع PostgreSQL
compose.handoff.yml   تشغيل QA معزول بلا مزودين حيين
```

- النظام عرض محلي بمالك تجريبي، وليس تطبيقًا متعدد المستخدمين مع مصادقة وعزل أمني جاهز للنشر العام.
- التوصيات استشارية؛ لا تكتب سجلات المزرعة، ولا تشخّص أمراضًا أو تتنبأ بخسارة المحصول.
- متوسط التعادل وتكلفة الكيلو للموسم يحسبان على الكمية المباعة + المتبقية القابلة للتسويق، وليس المتبقية وحدها.
- تم فحص PDF الفعلي بالعربية والإنجليزية، وفحص رحلة المتصفح على Chrome وقاعدة SQLite وPostgreSQL معزولة.
- الاتصالات الحية بـ Groq/Azure/Open-Meteo، وجودة الصوت الفعلية، وتشغيل Docker في بيئة المراجعة بقيت غير متحققة. لا تُفسر نجاح الاختبارات المموهة كنجاح اتصال حي.
- `requirements.txt` يستخدم نطاقات إصدارات؛ التثبيت اللاحق قد يحل اعتماديات مختلفة. أعد الاختبارات على الجهاز الجديد.
